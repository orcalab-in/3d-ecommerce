# Design decisions

Every place a physical dimension or engineering trade-off was picked without an explicit spec value. Change the default in the relevant `products/*.py` `DEFAULTS`/`PARAM_SPEC` after test prints; update this file to match.

## Checkpoint 1 -- Photo lamp

- **Slot clearance: 0.4mm** (`slot_clearance_mm` default), carried over from the `lithophane.py` prototype's `stand_stl`. Loose enough for PLA warp tolerance on an A1 at 0.2mm layers without a visibly sloppy fit.
- **Stand slot geometry**: panel slot starts 12mm from the stand's front edge (`front_y` in `products/photo_lamp.py::_build_stand`); LED board slot follows after `stand_gap_mm` (default 10mm) diffuser gap. Both carried over from the prototype.
- **Caption embossing height: raised 0.6mm** (`caption_depth_mm` default), size 6mm em-square (`caption_size_mm`), font Open Sans. Centered on the stand's front lip, embedded 0.2mm into the stand body so the two independently-watertight solids fuse at the seam when printed (the same "embed slightly, don't just touch" trick used for the terrain/route joint in product 4 -- see below).
- **Rounded corner radius: default 0, max 20mm** (`corner_radius_mm`). Clamped to `min(radius, width/2, height/2)` in `mesh.corner_mask` so a radius request larger than the panel can't produce a degenerate/self-overlapping shape.
- **Font size semantics**: `size_mm` in `text.emboss_text` is the font's em-square height in mm, not cap-height or x-height -- a simple, easy-to-reason-about approximation rather than trying to read per-font metrics (OS/2 table cap-height etc.) for a small cosmetic feature.

## Engineering decisions that affect every product

- **No box-union CSG anywhere composite parts are needed.** The natural first instinct for a "floor + walls with gaps" shape (a stand, later a puck base, a backlit frame) is a union of touching `box()` calls -- this is what the prototype did, and slicers handle it fine visually, but it does NOT pass strict watertightness validation: a wall segment's footprint is a subset of the floor's footprint beneath it, so the touching faces are only *partially* coincident and can't be exactly cancelled. `mesh.slotted_base` instead builds these shapes as a single **stepped heightmap** (floor level everywhere, floor+height everywhere except the slot y-ranges) fed through the same `ruled_grid_solid` primitive used for lithophane panels -- genuinely one watertight solid, no seams. Each height step is encoded as a tight (`step_eps` = 0.001mm) pair of grid rows at the two levels so it reads as vertical rather than a ramp. Any later product needing a similar stepped/recessed shape (puck base, backlit box frame) should use this same technique, not box unions.
- **Grams/print-time reuse meshcheck's volume.** `api.generate` calls `meshcheck.check_mesh` once per object and reuses its `volume_mm3` for both the watertightness verdict and the weight/time estimate, instead of three separate full-mesh passes. On a laptop, `check_mesh`'s vertex/edge dedup is the dominant cost for a fine lithophane mesh (millions of triangles) -- worth avoiding running it twice. Vertex merging inside `check_mesh` also packs `(x,y,z)` into a single void-typed key before `np.unique` rather than using `axis=0` (which goes through a much slower generic multi-column lexsort); together these keep a full-size (150x200mm, res 0.2mm) photo lamp job around ~3s, under the 5s/job budget.
- **Text-embossing robustness has a per-glyph safety net.** Ear-clipping a polygon-with-holes (needed for any letter with a counter: b/d/o/p/q/e/g/B/... ) is a well-understood technique but a genuinely tricky one to get exactly right in floating point -- several real bugs were found and fixed building this (a duplicate bridge vertex, a bridge nudge landing on a meshcheck rounding boundary, two code paths silently re-deriving slightly different cleaned polygons). After those fixes, both bundled fonts render the full A-Z/a-z/0-9 set cleanly except a small handful of characters (~2-10 depending on font/backend) that still occasionally defeat the triangulator on specific glyph geometry. Rather than chase 100% coverage indefinitely, `text.emboss_text` validates every glyph's mesh before including it and **drops** (with a warning collected into `JobResult.warnings`) any glyph that can't be made watertight -- the cursor still advances correctly, so spacing is preserved and the rest of the caption is unaffected. A broken caption character is a much smaller problem than a broken print file.
